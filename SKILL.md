# `monte-carlo-analyst`: Вероятностное моделирование рисков методом Монте-Карло

Специализированный аналитический навык вероятностного моделирования методом Монте-Карло (`10 000+` симуляций) без тяжёлых внешних зависимостей (работает на стандартной библиотеке Python 3 и автоматически включает векторное ускорение при наличии `NumPy`). Решает ключевую проблему детерминированных оценок («синдром студента», скрытые риски параллельных веток, кассовые разрывы).

## Фраза запуска и конвенция ответа

- **Фраза пользователя:** `«Монте-Карло, детка»` (или запрос на вероятностный аудит проекта, сроков, рисков, бюджета).
- **Обязательный мгновенный ответ ассистента:** **`«Принято, босс. Крутим рулетку!»`** (строго $\le 5$ слов), после чего запускается моделирование через расчётный скрипт `mc_engine.py`.

## Архитектура и 3 режима анализа

Расчётный движок реализован в скрипте `skills/monte-carlo-analyst/scripts/mc_engine.py` и поддерживает 3 специализированных режима:

| № | Режим (`--mode`) | Назначение и область применения | Математическое ядро и выходные метрики |
| :-: | :--- | :--- | :--- |
| **1** | **`flow`** | Прогнозирование сроков закрытия бэклога и пропускной способности продуктовых/инженерных команд (Scrum / Kanban). | • Контрольные карты Шухарта (`XMR`: $\overline{X}$, $\overline{MR}$, границы `UNPL` / `LNPL`)<br/>• Фильтр статистической стабильности процесса<br/>• Бутстрэп `MC-When` (за сколько периодов закроем $N$ задач)<br/>• Бутстрэп `MC-How-Many` (сколько задач сделаем за $T$ периодов)<br/>• Перцентили надёжности `P50 / P70 / P85 / P95` |
| **2** | **`pert`** | Планирование расписания проектов и релизов при наличии графа предшественников и зависимостей между задачами (`DAG`). | • 3-точечные оценки `PERT` ($O$, $M$, $P$) и `Beta`-распределения<br/>• Топологическая сортировка графа зависимостей и поиск критического пути на каждой из 10 000 симуляций<br/>• **Индекс критичности задач (`Criticality Index %`)**<br/>• Инженерный буфер безопасности расписания ($\Delta = P85 - P50$) |
| **3** | **`finance`** | Финансовое стресс-тестирование юнит-экономики, P&L, бюджетов запуска и оценка риска кассового разрыва. | • Стохастические потоки доходов и расходов (`pert`, `triangular`, `normal`, `lognormal`, `uniform`, `constant`)<br/>• Вероятность получения убытка $P(\text{Profit} < 0)$<br/>• Показатель **`Value at Risk (VaR 95%)`** (максимальный убыток в 5% худших сценариев)<br/>• Ранговый анализ чувствительности параметров (`Sensitivity Analysis`) |

## Режим 1: `Flow` (Прогнозирование задач и потока)

Применяется для продуктовых и инженерных команд при наличии исторической выборки закрытых задач за прошлые периоды (спринты, недели, дни).

### Алгоритм:
1. **Карта XMR (`Moving Range`):** проверка процесса на статистическую управляемость. Если в истории есть аномалии за пределами естественных границ ($\text{UNPL} = \overline{X} + 2.66 \cdot \overline{MR}$), процесс нестабилен, и моделирование сопровождается предупреждением о рисках.
2. **`MC-When`:** бутстрэп-выборка с возвращением для оценки числа периодов на закрытие $N$ задач из бэклога.
3. **`MC-How-Many`:** расчёт объёма задач, который гарантированно закроется за $T$ спринтов/недель с заданной вероятностью.

### Запуск:
```bash
python3 skills/monte-carlo-analyst/scripts/mc_engine.py --mode flow --data '{"history": [4, 5, 2, 6, 3, 5, 4, 7, 2, 5], "backlog_items": 25, "target_periods": 6}'
```
*(На Windows допускается запуск через `python` или `py` вместо `python3`).*

## Режим 2: `PERT` (Расписание, зависимости и критический путь)

Применяется на этапе планирования архитектуры, проектов и фич при наличии перечня задач и зависимостей между ними.

### Алгоритм:
1. Каждая задача описывается тремя точками: $O$ (`Optimistic`), $M$ (`Most Likely`), $P$ (`Pessimistic`).
2. Расчёт математического ожидания и стандартного отклонения по `Beta-PERT`:
   $$\mu = \frac{O + 4M + P}{6}, \quad \sigma = \frac{P - O}{6}$$
3. На каждой из `10 000` итераций строится расписание (`Early Start / Early Finish`, `Late Start / Late Finish`) и определяется критический путь.
4. Вычисляется **Индекс критичности** — процент симуляций, в которых задача имела нулевой резерв времени (`slack = 0`) и оказывалась узким горлышком всего проекта.
5. Расчёт резерва времени на риски: $\Delta = P85 - P50$.

### Запуск:
```bash
python3 skills/monte-carlo-analyst/scripts/mc_engine.py --mode pert --data '{"tasks": [{"id": "T1", "name": "Архитектура", "optimistic": 2, "most_likely": 3, "pessimistic": 6, "depends_on": []}, {"id": "T2", "name": "Бэкенд", "optimistic": 4, "most_likely": 7, "pessimistic": 12, "depends_on": ["T1"]}, {"id": "T3", "name": "Фронтенд", "optimistic": 3, "most_likely": 5, "pessimistic": 10, "depends_on": ["T1"]}, {"id": "T4", "name": "Релиз", "optimistic": 2, "most_likely": 3, "pessimistic": 5, "depends_on": ["T2", "T3"]}]}'
```

## Режим 3: `Finance` (Финансовые риски и маржинальность)

Применяется для оценки окупаемости продуктов, юнит-экономики, бюджетов разработки и рисков кассового разрыва.

### Алгоритм:
1. Задаются потоки доходов (`revenues`) и расходов (`costs`) с вероятностными распределениями (`pert`, `triangular`, `normal`, `lognormal`, `uniform`, `constant`).
2. Моделируется распределение чистого денежного потока (`Net Profit / Cash Flow`).
3. Оценивается вероятность закрытия в минус: $P(\text{Profit} < 0)$.
4. Рассчитывается **`VaR (Value at Risk 95%)`** — максимальный убыток в 5% худших сценариев.
5. Строится **анализ чувствительности** (корреляция каждого входного параметра с итоговой прибылью).

### Запуск:
```bash
python3 skills/monte-carlo-analyst/scripts/mc_engine.py --mode finance --data '{"revenues": [{"name": "Подписки SaaS", "distribution": "pert", "optimistic": 800000, "most_likely": 1200000, "pessimistic": 1800000}], "costs": [{"name": "ФОТ команды", "distribution": "constant", "value": 900000}, {"name": "Маркетинг и облачная инфраструктура", "distribution": "pert", "optimistic": 150000, "most_likely": 250000, "pessimistic": 500000}]}'
```

## Правила интерпретации квантилей для принятия решений

- **`P50` (Медиана):** вероятность выполнения `50/50`. Подходит для внутренних ориентиров команды, но **категорически непригодно для внешних дедлайнов и коммерческих договоров** (каждый второй проект будет сорван).
- **`P70–P85` (Инженерный стандарт):** рекомендуемый уровень коммитмента для договоров с клиентами, спринт-планирования и защиты бюджета. Оптимальный баланс между конкурентоспособностью и защитой от непредвиденных задержек.
- **`P95` (Консервативный / SLA):** жёсткие дедлайны с высокими финансовыми штрафами или критические инфраструктурные запуски.
